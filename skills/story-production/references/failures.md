# Operational failure reference

All generated movies live in videos/<new-id>/. Existing films without a production ownership marker cannot be overwritten. `work/failure.json` records the failing command and reason; no stage silently falls back to unrelated animation or paid services.

The first PocketSphinx version tried lacked a usable binary wheel in this environment; 5.0.4 is pinned and installed with --only-binary to avoid requiring a compiler toolchain. Alternative pronunciation labels such as was(2) are normalized before exact transcript comparison. These were implementation fixes, not evidence of general alignment accuracy.

No `apad` or open-ended audio mix runs in the new production adapter: conversions have finite -t and subprocess timeouts. Music remains the original project's finite procedural synthesizer. Disk/file sizes are checked. Long jobs still need a stronger queue/checkpoint/recovery service before unattended production claims.

Input changes invalidate source/config/runtime hashes. Rendering requires matching technical preflight and visual-review records. A review record is an operator declaration and cannot prove a person opened the images; the Skill requires actually opening them.
